# Spring JPA Integration

A Maven multi-module project demonstrating two approaches to integrating Spring with JPA (Hibernate) over an Oracle HR sample schema, using an in-memory H2 database for tests.

## Modules

| Module               | Purpose                                                                          |
|----------------------|----------------------------------------------------------------------------------|
| `xml-config`         | Spring 4 + XML-based configuration (`applicationContext.xml`, `persistence.xml`) |
| `annotations-config` | Spring 5 + Java `@Configuration` classes (no XML, no `persistence.xml`)          |

Both modules implement the same domain and DAO logic, allowing a direct comparison between the two configuration styles.

## Prerequisites

- Java 8
- Maven 3.x

No external database is needed. Both modules use H2 in-memory (`jdbc:h2:mem:testdb`). The schema is auto-generated by Hibernate (`hbm2ddl.auto=create`) and test data is loaded from `src/main/resources/sql/data.sql`.

## Build & Run Tests

```bash
# Build and test all modules
mvn clean install

# Test only one module
mvn test -pl annotations-config
mvn test -pl xml-config

# Run a single test class
mvn test -pl annotations-config -Dtest=CountryServiceIT

# Run a single test method
mvn test -pl annotations-config -Dtest=RegionServiceIT#getAllRegionsWithJoinFetch
```

## Domain Model

The schema models an HR system with the following entity hierarchy:

```
Region
 └── Country (many per Region)
      └── Location (many per Country)
           └── Department (many per Location)
                └── Employee (many per Department)
                     ├── manager → Employee (self-reference)
                     ├── Job (ManyToOne)
                     └── JobHistory (composite PK: employee_id + start_date)
```

Notable mapping details:
- `Employee` has optimistic locking via `@Version`.
- `JobHistory` uses `@EmbeddedId` (`JobHistoryPK`).
- `DepartmentDetails` is an `@Embeddable` type embedded in `Department`.
- `Region.countries` is `FetchType.EAGER` (used to demonstrate the N+1 problem and its `JOIN FETCH` fix).
- `Employee.department` is `FetchType.EAGER`; `Employee.job` and `Department.location` are `FetchType.LAZY`.

## Module Architecture

### `xml-config`

Spring context is assembled from three XML files under `src/main/resources/spring/`:

- **`application-config.xml`** — root context, imports the others and sets up component scanning.
- **`datasource-config.xml`** — defines the `DataSource` bean (BoneCP connection pool).
- **`data-access-config.xml`** — defines `EntityManagerFactory` (pointing to `persistence.xml` for the `HR_PU` persistence unit), `JpaTransactionManager`, and `SharedEntityManagerBean`; enables `<tx:annotation-driven/>` and `<jpa:repositories>`.

Entity classes must be listed explicitly in `META-INF/persistence.xml`. The `BaseDaoImpl` in this module includes manual `EntityTransaction` handling (begin/commit/rollback) as an illustration of programmatic transaction management; Spring's declarative transactions supersede this in practice.

Two standalone utilities exist for use outside a Spring container:
- `EntityManagerUtils` — lazily creates a singleton `EntityManagerFactory` / `EntityManager` via `Persistence.createEntityManagerFactory("HR_PU")`.
- `PersistenceManager` — enum singleton wrapping an `EntityManager`.

### `annotations-config`

Spring context is built from two `@Configuration` classes under `edu.link.config`:

- **`AppConfig`** — `@ComponentScan("edu.link.jpa")` + `@Import(DatabaseConfig.class)`. Entry point for tests.
- **`DatabaseConfig`** — declares all infrastructure beans:
  - `DataSource` (HikariCP) — properties read from `classpath:jpa-training.properties`.
  - `LocalContainerEntityManagerFactoryBean` — scans `edu.link.jpa.model` (no `persistence.xml` needed).
  - `HibernateJpaVendorAdapter` + `JpaTransactionManager`.
  - `@EnableTransactionManagement` and `@EnableJpaRepositories("edu.link.jpa.dao")`.

Services (`@Service @Transactional`) are the transaction boundary. DAOs are `@Repository` beans injected with `@PersistenceContext EntityManager` via `BaseDaoImpl`.

### DAO layer (both modules)

`BaseDaoImpl<T>` provides generic CRUD helpers:

| Method                  | Underlying JPA call        |
|-------------------------|----------------------------|
| `persist(T)`            | `em.persist`               |
| `read(Class, id)`       | `em.find`                  |
| `update(T)`             | `em.merge`                 |
| `remove(T)`             | `em.remove`                |
| `readAll(hql, Class)`   | `TypedQuery.getResultList` |
| `select(CriteriaQuery)` | Criteria API query         |

Concrete DAO implementations extend `BaseDaoImpl` and add entity-specific JPQL, native SQL, or named queries (`@NamedQuery` on the entity).

## Key JPA Concepts Demonstrated

- **N+1 problem** — `RegionDaoImpl.getAllRegions()` triggers N additional queries when iterating `region.getCountries()` because `countries` is `EAGER` but loaded separately per region. Fixed in `getAllRegionsWithJoinFetch()` using `JOIN FETCH`.
- **Named queries** — `Employee.findByDepartment` defined via `@NamedQueries` on the entity.
- **Native queries** — `DepartmentDaoImpl.getDepartmentDetails()` uses `em.createNativeQuery` with positional parameters.
- **Optimistic locking** — `Employee.version` field with `@Version`.
- **Composite primary key** — `JobHistory` + `JobHistoryPK` with `@EmbeddedId`.

## Configuration Files

| File                            | Module     | Purpose                                                                |
|---------------------------------|------------|------------------------------------------------------------------------|
| `jpa-training.properties`       | both       | JDBC URL, credentials, Hibernate dialect/DDL settings                  |
| `META-INF/persistence.xml`      | xml-config | Persistence unit definition with explicit entity list                  |
| `spring/datasource-config.xml`  | xml-config | DataSource bean (BoneCP)                                               |
| `spring/data-access-config.xml` | xml-config | EntityManagerFactory, TransactionManager                               |
| `sql/data.sql`                  | both       | Test data (regions, countries, locations, departments, jobs, employees) |
